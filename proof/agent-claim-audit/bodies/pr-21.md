## Summary

Turns Anti-Slop's one **benchmark-supported** primitive (locator-accuracy-v4 mechanical lineage) into a reusable, self-dogfooded **deterministic citation-lineage tool**. No frozen eval artifact (v2/v3/v4) is touched; no canon is promoted; no source-card review status is lifted.

## Tool hardening — `scripts/gate_citation_lineage.py`

- **`--root`**: injectable corpus/registry root; default behaviour preserved (a plain `gate FILE` run is existence-only, as before).
- **`--require-reviewed`**: forward-reference check — every source-card reference must resolve to a **reviewed** card (a file's own `card_id` self-reference excepted). The `x-vs-y` backtick heuristic now resolves against the eval-case namespace so eval case IDs aren't misread as dangling claim-card refs.
- **self-test**: expanded to **7 genuine checks** — existence; nonexistent-ref caught; default vs reviewed mode; unreviewed-forward-ref caught; self-reference allowed; **`--root` injection actually exercised** (a second fixture root where the same file's card is unreviewed makes the same input fail).

## Dogfood + demo

- **`make citation-dogfood`**: runs `--require-reviewed` over the KB's own lineage artifacts (corpus cards/maps + eval design/decision docs; **excludes** `model-outputs/` + `judge-packet/outputs/`, which are test artifacts that may cite fabricated lineage by design). **PASSES at 321 files / 3023 references** — the KB is clean.
- **`make demo`** (`scripts/demo_citation_lineage.py`, `proof/citation-lineage-demo/`): `compile_brief` → static sample corrected note → `gate_citation_lineage` → receipt, **fully offline (no API key, network, model runtime, or raw book)**. PASSES the good sample and FAILS a `BK-9999-card-001` slop sample.

## Claim narrowing + gate tiering

- The broad "reduce slop / improve advice" claim is the **program hypothesis, explicitly unproven** (the `criteria_prompted_no_sources` ceiling stands); only the **narrow v4 mechanical-lineage claim** is benchmark-supported.
- Gates tiered: **deterministic** — citation-lineage (*implemented, benchmark-backed*), raw-text/`check-raw` (*implemented*), quote-limit / authority-order (*scaffold-only* per `gates/gate-specs.yaml`); **heuristic/advisory** — no-universalization (*implemented*), source-diversity / canon-duplication / contradiction (*scaffold-only*).

## BK-0023 finding (truthful; differs from the planning premise)

The `BK-0023-card-001` card named in planning as a "not yet reviewed" defect is in fact **`operator_review_status: reviewed`** (operator-approved 2026-05-21), and **all references to it resolve** (the dogfood gate confirms). Downgrading its references to "not yet reviewed" would have written a **falsehood** and misrepresented an operator-approved card, so it was **not** done. The one genuinely-stale clause — `BK-0023-card-001` says BK-0002 has no reviewed source card, but `BK-0002-card-001` now exists and is reviewed — is **recorded as a follow-up**, not silently edited into an operator-approved card. See "single best next PR" below.

## Residual risks
- The dogfood model-outputs/ exclusion is defensible and forward-looking but not load-bearing today (current eval outputs cite no unresolved lineage).
- The `--require-reviewed` self-reference exception trusts the citing file's own `card_id` (not exploitable in a one-card-per-file KB; future hardening could key it on the canonical card path).
- The gate checks reference *resolution/review status*, not semantic truthfulness — it cannot detect the stale BK-0002 prose clause (a contradiction, not a broken reference).
